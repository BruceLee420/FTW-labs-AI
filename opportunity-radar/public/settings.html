Configuration · local service

Settings

1 · Résumé directory

Set OPPORTUNITY_RADAR_RESUMES_DIR in opportunity-radar/.env (or your shell) to the folder holding your résumé variants (PDF, DOCX, TXT, Markdown). Default: opportunity-radar/private/resumes/source, which is git-ignored. The service never shows the resolved path here — only whether it is configured and reachable.

Open the Résumé Library →

2 · AI (advisory)

Environment variables OPPORTUNITY_RADAR_AI_PROVIDER, OLLAMA_BASE_URL and OLLAMA_MODEL set the defaults; overrides saved here are stored in the local database.

4 · Source adapters

Only permitted sources are supported: official ATS APIs, feeds that allow syndication, and fixtures. Configure suggested targets with OPPORTUNITY_RADAR_GREENHOUSE_BOARDS (comma-separated board tokens) and OPPORTUNITY_RADAR_RSS_FEEDS (feed URLs); add hostnames to refuse with OPPORTUNITY_RADAR_URL_DENYLIST. Sites that prohibit automation are always refused.

5 · Data

Export JSON Everything except résumé text: opportunities, applications, drafts, follow-ups, evaluations, audit.

6 · Access token

Needed only when the service runs with OPPORTUNITY_RADAR_AUTH_TOKEN (required when it binds to anything other than loopback). Saved in this browser's sessionStorage and localStorage under ftw_radar_token so the dashboard widget can use it. It is sent only to this API, as a bearer header.

7 · AI advisory disclaimer

Advisory — review before acting

Every model output in this tool is advisory. Deterministic rules run first and are always shown with their evidence; a model can raise a scam-risk score but never lower it below the rules' result. Model JSON is validated against strict schemas and rejected when it does not conform. Verification wording is graded — "likely legitimate", "needs manual verification", "high risk" — never "safe". Drafts are grounded only in the résumé profile you select; every claim is paired with the résumé fact it came from, and claims whose source cannot be found are flagged. Read and edit every draft before approving it — you are the author of what gets submitted.

8 · No automatic applications or messages

Opportunity Radar is not an auto-apply bot. There is no code path that submits an application form, uploads a résumé or any file to a third party, sends an email or platform message, or logs in to, scrapes or automates LinkedIn or any site that prohibits it. It prepares material for you to review, edit and approve, then shows the official application URL and a checklist. You submit outside the system and record the result; follow-up emails are drafted and displayed, never sent.
